# 広告主に合わせた全体設計（案）

- 状態：案 v2（2026-11-06）。タウンライフからの指摘（PR表記・ネガティブ表現）を反映。親Issue #1。前提：[site-design.md](site-design.md)、[privacy-architecture.md](privacy-architecture.md)
- 本線：タウンライフ土地活用、タウンライフ家づくり（注文住宅）。単価が高く、3Dシミュレーションを使う人と重なる
- サブ：タウンライフ空き家解決、タウンライフ土地解決、タウンライフ不動産相続。トップページで状況ごとに分けて案内する

## 1. 考え方

広告主ごとに「誰が申し込むと成果になるか」が違う。サイトは**利用者の状況**で入口を分け、3Dで自分の土地の可能性を見てもらったあと、**状況に合う1社だけ**をはっきり出す。広告を並べすぎない（質の低い申込みは否認・提携解除の原因になり、高単価案件ほど厳しい）。

| 広告主 | 合う人 | このサイトで分かる手がかり | 3Dの役割 |
|---|---|---|---|
| 家づくり（本線） | 土地がある／買う予定で、自宅を建てたい | 使い道＝自宅、状況＝土地を持っている・購入検討中 | 「この土地にこの大きさの家」→「実際の間取りと見積もりを取り寄せる」 |
| 土地活用（本線） | 土地を持っていて、収入を得たい | 使い道＝賃貸・店舗・駐車場、面積が大きい、市街化調整区域（建物以外の活用） | 「アパートなら何戸・延床どれくらい」→「収支プランを取り寄せる」 |
| 空き家解決 | 古い家・空き家を持っている | 敷地内に既存建物（PLATEAU・地理院の建物データで分かる）、状況＝空き家がある | 「建て替え・解体して駐車場」などの案を見せる |
| 土地解決（サイト名：タウンライフ土地売却） | 使い道や売り方が分からない土地を持っている（相続した地方の実家、使っていない田畑、売れなかった土地）。一括査定 | 市街化調整区域、道路に接していない、狭い・細長い、山林・農地 | 「建てられる大きさがごく小さい／原則建てられない」と分かったときの次の一歩 |
| 不動産相続 | 相続した・これから相続する | 状況＝相続した・相続予定 | 相続した土地で何ができるかを見せたうえで、手続き・売却の相談先を案内 |

## 2. ページの役割と広告の置き場所

| ページ | 広告 | 役割 |
|---|---|---|
| トップ（LP） | **載せない** | ツールの入口に専念。【PR】表記がいらないのでファーストビューを入口に使える |
| 公開ガイド：土地活用 | あり（【PR】2箇所以上） | 賃貸・店舗・駐車場を選んだ人の受け口。提携申請の審査用ページを兼ねる |
| 公開ガイド：家づくり | あり（【PR】2箇所以上） | 自宅を選んだ人の受け口。審査用ページを兼ねる |
| 公開ガイド：空き家・土地売却・相続 | あり（サブ案件の承認後に追加） | トップのサブの入口の受け口 |
| 結果ページ（利用者ごとのURL・noindex） | あり（【PR】2箇所以上） | 実質の成果地点 |

### トップページの入口（広告リンクなし）

「あなたの状況は？」で入口を分ける。カードの行き先は**ツールか自サイトのガイド**だけで、広告主へは直接つながない。

1. この土地に家を建てたい → ツール（使い道＝自宅）
2. 土地を活用して収入を得たい → ツール（使い道＝賃貸）
3. 空き家・古い家がある → ツール（状況＝空き家）／空き家ガイド
4. 使い道や売り方が分からない土地がある → ツール（状況＝土地に困っている）／土地売却ガイド
5. 相続した・これから相続する → ツール（状況＝相続）／相続ガイド

入口の選択は使い道・状況の初期値になるだけで、あとから変えられる。

### 【PR】表記の位置（タウンライフの指定：ファーストビュー＋任意の場所、計2箇所以上）

- ガイドページ：記事タイトルの横、各サービス紹介の見出しの直前
- 結果ページ：ヘッダーのタイトルの横（1箇所目）、3案の下の「次のステップ【PR】」枠の見出し（2箇所目）
- 表記の文字は【PR】で統一。実装したらタウンライフ運営事務局のフォームで連絡する

## 3. 結果ページでの広告の選び方

1回の結果で出す広告は**主に1つ、補助に1つまで**。

| 条件（上から順に判定） | 主 | 補助 |
|---|---|---|
| 市街化調整区域 | 土地活用（駐車場・資材置き場・太陽光など建物以外） | 土地解決 |
| 道路に接していない／建てられる大きさがごく小さい | 土地解決 | 土地活用 |
| 状況＝相続 | 不動産相続 | 使い道に合わせて家づくり／土地活用 |
| 状況＝空き家、または敷地内に既存建物あり | 空き家解決 | 使い道に合わせて家づくり／土地活用 |
| 使い道＝自宅 | 家づくり | ― |
| 使い道＝賃貸・店舗・駐車場 | 土地活用 | ― |
| まだ決めていない（3つを比べる） | 表示中の案の使い道に合わせて切り替える | ― |

出す場所：

- **主**：3案のすぐ下の「次のステップ【PR】」枠。案の続きとして事実を書く
  - 家づくり：「この方向で、複数社の間取りプランと資金計画を無料で取り寄せる」
  - 土地活用：「この規模で、複数社の収益化プランと見積を無料で比較する」
  - 土地売却：「この土地の査定額を、複数社から無料で受け取る」
- 枠の中に事実として「複数社を選ぶと比べやすくなります」を添える（1社だけの申込みは成果にならない条件があるため。ただし申込みをせかす書き方はしない）
- 一度クリックした枠は、同じ端末では目立たせずに小さく出すだけにする（同一人物の2回目以降は成果にならないため。端末内の記録だけで判定し、サーバーには持たない）
- **補助**：参考情報カードの「確認したい点」の下など、内容に関係する場所に1つ
- 広告は、ASPから発行されたURLが入っている枠だけ表示する（今の仕組みのまま）

## 4. 守ること

- **PR表記**：2.の位置に【PR】を付け、移動先が広告主のサイトであることを書く（景品表示法のステマ規制とタウンライフの指定）
- **ネガティブ表現の禁止**（タウンライフの表現ガイドライン。広告を載せるページすべて）
  - タイトル・小見出し・画像に、最悪・悪評・悪質・最低・後悔・デメリット・失敗・やばい・嘘・怪しい・危険・危ないなど、印象の悪い言葉を使わない
  - タイトルを「？」で終えない
  - 悪い点を挙げてから良い結論でまとめる書き方、口コミサイトの否定的な声の引用もしない
  - タイトルは「土地活用プランの比べ方」「間取りプランを取り寄せる流れ」のような事実を述べる形にする
  - 自サービスの注意書き（建築できることを保証しない、等）は広告主への表現ではないので、従来どおり置く。ただし見出しは「ご利用にあたって」など中立の言葉にする
- **誤解させない**：「この3Dの家を建ててくれる」「必ず建てられる」と読める書き方はしない。3Dは参考で、提案は各社が作るものと明記する
- **申込みを強く誘わない**：「今だけ」「申し込まないと見られない」はしない。3D・規模・参考情報は申込みの有無にかかわらず無料で全部見られる
- **個人情報は持たないまま**：申込みは利用者が広告主のページで直接行う。こちらから広告主へ住所・連絡先は渡さない
- **各プログラムの規約**：否認条件（重複・本人以外・対象外エリアなど）、禁止事項（リスティング・SNS広告・特定の表現）を承認時に確認して、ここに追記する

## 5. 計測

- 今ある記録（入力の進み具合、広告の表示・クリック）に、**入口・状況・表示した枠**を加える
- 成果（申込み・承認）はASPの管理画面で見る。枠ごとにサブIDを付けられるプログラムなら付け、入口別の承認率を比べる
- 見る数字：入口別の「結果まで進んだ割合」「広告クリック率」「承認数」。本線2つの承認数を最優先にする

## 6. 実装の順番

0. 公開ガイド2本（土地活用・家づくり）と、結果ページの【PR】配置を先に作る → その状態で本線2件の提携申請 → 承認後にリンクを入れる
1. 広告枠を5つに増やす（`worker/affiliates.ts`。URLは承認後に入れる）
2. 結果ページの広告の選び方を3.の表のとおりにする（調整区域・既存建物・状況を使う）
3. 状況の選択肢を「土地を持っている／購入を検討中／空き家がある／相続した・相続予定／土地に困っている／情報収集」に変える
4. トップページを5つの入口にする（スマホの画面構成案に合わせて作り直す）
5. 敷地内の既存建物を判定する（今の周辺建物の読み込みを使う）

## 7. まだ分かっていないこと

- 土地活用の対象にならない土地（面積の下限、地域）があるか
