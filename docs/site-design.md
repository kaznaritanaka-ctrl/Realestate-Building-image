# サイト全体設計（Phase 1 MVP）

- 対象：`https://realestate.ai-investment-research.net/`（土地の未来図｜AI建築イメージ生成）
- 状態：確定版v1（2026-11-05）。親Issue #1。「Q」付きの項目は**2026-11-05にすべて推奨案で決定**（末尾の決定一覧）。
- 前提：一人運営。事業者への営業・個人情報の第三者提供はしない。収益はASPアフィリエイト。

---

## 1. 画面構成（ルーティング）

| パス | 画面 | 公開 | 備考 |
|---|---|---|---|
| `/` | LP | index | 現行の公開準備ページを発展させる |
| `/new` | 入力ウィザード | index | 6ステップ（§2） |
| `/j/:token` | 受付・進捗ページ | noindex | 即時3D＋規模を表示しながら写真品質の生成を待つ |
| `/r/:token` | 結果ページ | noindex | 3案・規模・概算・注意書き・評価・PRリンク |
| `/go/:slot` | 広告リンクの中継 | noindex | クリックを記録してASPのURLへ302リダイレクト |
| `/privacy` `/ad-policy` | 方針 | index | 作成済み |
| `/terms` | 利用規約 | index | **新規作成**（生成物の権利・免責・禁止事項） |
| `/delete` | データ削除依頼 | noindex | トークンまたはメールで削除を受け付ける |
| `/admin/*` | 管理画面 | 非公開 | Cloudflare Accessで保護。ジョブ一覧・再実行・統計 |

`:token` は推測できない長さのランダム値（128bit以上）とし、URLを知っている人だけが見られる方式にする。ログインは作らない。

## 2. 入力ウィザード（`/new`）

| Step | 入力 | UI | 備考 |
|---|---|---|---|
| 1 | 場所 | 住所検索 → 地図（航空写真）に移動 | 住所の検索は国土地理院の住所検索API等（Q地域） |
| 2 | 敷地の形 | 航空写真の上で角をクリックして多角形を作る。面積を自動で計算 | 面積・辺の長さを手で修正可。複数筆はまとめて1つとして描く |
| 3 | 前面道路 | 道路に接する辺をタップ → 幅員を「4m未満／4〜6m／6〜12m／12m以上」から選ぶ | 容積率の道路幅員制限に使う |
| 4 | 法規制 | 用途地域・建ぺい率・容積率を座標から自動取得して表示。「不明」なら選択か「わからない」 | 「わからない」なら住居系の代表値で保守的に計算し、その旨を表示 |
| 5 | 目的 | 3案の構成（Q3案）、外観テイスト（Q）、検討段階、事業者への相談希望の有無 | 検討段階と相談希望は広告の出し分けと分析に使う |
| 6 | 通知先 | メールアドレス、利用規約への同意、任意のお知らせメール同意（初期値OFF）、Turnstile | 送信 → `/j/:token` へ |

- 地図はMapLibre GLと国土地理院タイル（航空写真・標準地図）。出典表示が必要（利用条件は要確認）。
- 入力途中の内容はブラウザに一時保存する（失敗しても続きから入力できる）。

## 3. 生成の流れ

```
送信 ─▶ Worker: 検証・Turnstile確認・上限チェック ─▶ D1にjob登録 ─▶ /j/:token
           │
           ├─ 同期処理：ボリュームエンジン（TS）で3案の形状とglTF・規模数値を計算 → R2保存
           │      └▶ /j/:token に即時3D（three.js）と規模表を表示
           │
           └─ 非同期処理：GPU runner（自宅Windows）がpullで取得
                  Blender（形状→レンダリング・Depth・マスク）→ ComfyUI（仕上げ）
                  → QC（マスクとのIoU。基準未満なら再生成、上限2回）→ R2へアップロード
                  → complete → Worker が完了メールを送信 → /r/:token
```

- ジョブの状態：`queued → leased → rendering → qc → done`、ほかに `failed / expired / cancelled`。leaseは10分で切れ、heartbeatが止まれば `queued` に戻す。
- runner用API：`POST /api/runner/lease`、`/heartbeat`、`/complete`、`/fail`。runner専用のトークンで認証する。R2へは署名付きURLで直接アップロードする。
- **GPUが止まっている間の挙動**：受付は止めない。進捗ページに「混雑中・完成までの目安」を表示する。24時間を過ぎたら「遅延のお詫び」メールを1通だけ送る。72時間で `expired` にする。
- 処理能力：1件10〜15分なので、24時間稼働で約100件／日が上限。**1日の受付上限を設ける（Q上限）**。

## 4. 結果ページ（`/r/:token`）

1. 3案を並べて表示（タブまたは横並び）。各案に写真品質の画像（正面・斜め）＋白模型の3D（回転できる）
2. 規模表：建築面積・延床面積・階数・戸数（B案）・建ぺい率と容積率の使用率
3. 概算工事費：坪単価の範囲 × 延床面積。出典と基準年を明記（Q概算）
4. 入力の確かさ：「確認済み／参考／不明」で各値を表示（例：用途地域＝参考、道路幅員＝利用者入力）
5. 注意書き（参考イメージであること・建築できることを保証しないこと）
6. 1クリック評価（👍／👎＋任意コメント）
7. **次の一歩**：用途に応じたPR表記付きのリンク（A→注文住宅の一括請求、B・C→土地活用の一括請求）。画像は無条件で提供し、申込みを条件にしない
8. 画像の保存（ダウンロード）・期限の表示・削除ボタン

## 5. メール

| 種別 | タイミング | 内容 |
|---|---|---|
| 受付 | 送信直後 | 受付番号・進捗ページURL |
| 完了 | 生成完了時 | 結果ページURL・保存期限（広告リンクは載せない） |
| 遅延 | 24時間経過時 | お詫びと進捗URL（1回だけ） |

- 送信手段：Cloudflare Email Service（Workersから直接送れる）を第一候補とし、使えなければResend等。SPF・DKIM・DMARCを設定する。
- 悪用対策：1メールアドレスにつき1日○件、1IPにつき1日○件、Turnstile。送るのは本人が依頼した通知だけなので、第三者宛てにメールを大量送信する経路にはならない。
- お知らせメール（販促）はMVPでは送らない。同意の有無だけ記録しておく。

## 6. データとプライバシー

| データ | 置き場 | 保持期間（案） |
|---|---|---|
| 入力（敷地多角形・用途など） | D1 `property_inputs` | 90日 |
| メールアドレス | D1 `contacts`（分析用テーブルとは分ける） | 90日（お知らせ同意者は同意撤回まで） |
| 生成画像・glTF | R2（非公開） | 30日（Q保持） |
| ファネルのイベント | D1 `events`（メールとは結び付けない仮名ID） | 1年 |
| 広告クリック | D1 `affiliate_clicks`（slot・用途・時刻） | 1年 |

- 期限切れのデータは毎日cronで削除する。`/delete` から即時削除もできるようにする。
- 外部の解析タグは入れない（CSPはscript-src 'self'のまま）。必要になったらCloudflare Web Analyticsを使う。

## 7. Cloudflare構成

| リソース | 名前（案） | 用途 |
|---|---|---|
| Worker | `realestate-site` | 静的アセット＋API（Hono）。既存のWorkerを置き換える |
| D1 | `realestate-db` | jobs / property_inputs / artifacts / contacts / consents / events / affiliate_clicks |
| R2 | `realestate-artifacts` | 生成物（非公開） |
| Turnstile | `realestate` | ボット対策 |
| Access | `/admin/*` | 管理画面の保護 |

投資系（ai-investment-*）とはD1・R2・シークレット・APIトークンを一切共有しない。runner用トークンはこのWorker専用にする。

## 8. 計測（KPI）

`lp_view → wizard_start → step_n_complete → submit → instant3d_view → job_done → mail_open（取れれば）→ result_view → rating → affiliate_click`。用途別・流入元別に、日次で `/admin` に出す。ASPの成果発生と承認はASPの管理画面で確認し、週1回手入力で突き合わせる。

## 9. 実装順

1. ボリュームエンジン（TS・単体テスト付き）＋3Dビューア
2. ウィザード（Step 1〜4）＋即時3D（ここまではGPUなしで公開できる）
3. D1・ジョブAPI・runner（Windows）・R2
4. メール・結果ページ・PRリンク・計測
5. 管理画面・データ削除cron・利用規約

**2が終わった時点で「即時3Dだけの版」を先に公開し、需要を測る**ことも可能（Q先行公開）。

## 決定事項（2026-11-05、全項目推奨案で承認）

| ID | 論点 | 決定 |
|---|---|---|
| Q3案 | 3案は「用途違い（自宅／賃貸／活用）」で固定か、「選んだ用途のなかでのバリエーション3つ」か | 用途違いで固定。用途を1つに絞った人には、その用途の規模違い3案に切り替える |
| Qテイスト | 外観テイストを選ばせるか（モダン／和モダン／ナチュラル等） | MVPは選ばせず、3案それぞれに合う外観を自動で決める |
| Q地域 | 対象地域は全国か、関西など限定か | 入力は全国OK。用途地域の自動取得は取れる地域だけで、取れなければ手入力 |
| Q上限 | 1日の受付上限、1人あたりの上限 | 全体30件／日、1メール2件／日から始める |
| Q保持 | 結果ページの保持期間 | 30日 |
| Q概算 | 概算工事費を出すか。賃貸の想定利回りも出すか | 工事費の範囲だけ出す。利回りは誤認リスクが高いので出さない |
| Qギャラリー | 利用者の同意を得て、生成例を公開ギャラリーに載せるか | MVPでは載せない。サンプルは自分で用意した架空の敷地を使う |
| Q先行公開 | GPU生成の前に「即時3Dだけの版」を公開するか | する（ASPの審査中にも需要を測れる） |
| QPC | Windows PCは24時間稼働させられるか、何時ごろ止まるか | 停止時間帯は受付を続け、目安時間を表示する |
| Q古家 | 古家付きの土地で、現況写真のアップロードを受け付けるか | MVPでは受け付けない（権利・個人情報・写り込みの負担が大きい） |
